Run a useful first website audit

Set a sensible crawl scope and turn findings into a short investigation list.

By Teja Priyan · Updated 27 October 2026

Start with a public website you can inspect

Use a public homepage for a site you own or have permission to analyze. Do not paste a preview URL that contains a secret, an account link or a session token. A crawl fetches pages on the server, so the target must be reachable from there. A website that loads in your signed-in browser may still be unavailable to TRACE.

Keep the first crawl small

Begin with the default scope rather than immediately increasing page count and depth. Look at the requested address, redirects and HTTP responses before interpreting a score. If the crawl found only a few pages, inspect robots rules, navigation links and whether the visible content depends on browser-side JavaScript. A server fetch does not guarantee the same view as an interactive browser.

  1. Run the demo first if you want to learn the interface without submitting a real target. Demo findings describe the demo dataset.
  2. Enter a public starting URL and review the crawl settings. Avoid unlimited parameter variations or unrelated subdomains.
  3. Watch progress and open the pages view. Compare discovered URLs with the sections you expected to find.
  4. Open a page’s evidence panel before acting on a warning. Check the response, heading, link or header that caused it.
  5. Select a few reproducible issues, fix them in the target site, and repeat a crawl with comparable settings.

Interpret an incomplete result

A timeout, denied request or blocked URL is evidence about that request, not proof that every visitor sees an error. Dynamic content, redirects and hosting limits can change the result. Keep the crawl time and settings with an exported report. When asking for help, share a public example and the specific finding rather than sending credentials or a confidential report link.
